## Design Context

### Users
- **Primary:** Vendedores de campo usando celular entre visitas a clientes — precisam de acesso rapido a vendas, cadastros e historico
- **Secondary:** Administradores no escritorio usando desktop/notebook — gerenciam relatorios, configuracoes, comissoes e dashboard executivo
- **Context:** Sistema de gestao comercial B2B usado durante jornada de trabalho, em ambientes variados (escritorio, campo, transito)
- **Job to be Done:** Registrar vendas rapidamente, acompanhar metas, gerar boletos, enviar notificacoes para empresas parceiras, consultar historico

### Brand Personality
- **3 palavras:** Moderno, Inteligente, Agil
- **Tom:** Profissional mas acessivel — transmite confianca sem ser frio
- **Emocao:** Confianca e profissionalismo — o usuario deve sentir que esta usando uma ferramenta seria e confiavel

### Aesthetic Direction
- **Visual tone:** Moderno e limpo, com hierarquia clara de informacao
- **Theme:** Light mode primario com dark mode completo (OKLch color system)
- **Fonts:** Manrope (body, 400-700) + Space Grotesk (headings, 500-600)
- **Icons:** Lucide React — stroke consistente, sem emojis
- **Radius:** 10px base (rounded-lg), cards 20px (rounded-2xl)
- **Shadows:** OKLch-based, hierarquia sm/md/lg/xl
- **Sidebar:** Sempre dark (slate-900), contraste com conteudo claro

### Anti-references (NAO deve parecer)
- Colorido demais / infantil (tipo Canva) — evitar gradientes decorativos sem proposito
- Muito denso / poluido (tipo ERP antigo) — manter espacamento generoso, hierarquia clara
- Evitar: emojis como icones, cores neon, animacoes excessivas, fontes fantasia

### Design Principles
1. **Clareza sobre decoracao** — Cada elemento visual deve servir a um proposito funcional. Espacamento, cor e tipografia comunicam hierarquia, nao decoram.
2. **Mobile-first, desktop-complete** — Vendedores no campo sao prioridade. Toda funcionalidade deve ser utilizavel em tela pequena. Desktop expande, nao reestrutura.
3. **Consistencia implacavel** — Um unico padrao de botao, label, dropdown, card e empty state em todo o sistema. Tokens semanticos (primary, accent, error) em vez de cores hardcoded.
4. **Feedback imediato** — Toda acao do usuario recebe resposta visual em menos de 300ms. Loading states, toasts de confirmacao, validacao inline.
5. **Acessibilidade como padrao** — WCAG AA minimo. Contraste 4.5:1, labels em todos os inputs, focus states visiveis, navegacao por teclado funcional.

### Technical Design Tokens
- **Colors:** OKLch color space, semantic tokens (--primary, --accent, --success, --warning, --error, --info)
- **Spacing:** 4px base scale (--space-1 through --space-12)
- **Typography:** Manrope body, Space Grotesk headings, scale 12/14/16/18/24/32
- **Transitions:** fast 150ms, normal 250ms, slow 350ms (cubic-bezier 0.4, 0, 0.2, 1)
- **Component library:** shadcn/ui (33+ components) + custom variants (CardStats, FormSelect, PageHeader, EmptyState)
